## Product Truth

Pact is a testnet-only programmable virtual spending card for one AI Agent.
An owner creates a virtual card, assigns one agent signer, sets a total cap,
per-transaction limit, expiry, and merchant allowlist, then funds the card's
Creditcoin Advance Testnet payment pool with native testnet CTC. The agent can
turn a natural-language request into a structured intent, but the blockchain
policy remains the authority: the owner and policy contract decide whether a
payment may settle.

The MVP includes:

- Creditcoin EVM Advance Testnet as the only target network.
- Native testnet CTC as the only payment asset, represented in contract calls
  by `address(0)` and in the product domain by `native-testnet-ctc`.
- Attestcoin ASC evidence as the source of a verified-credit record.
- OpenAI `gpt-5.6-luna` as the configured intent provider, subject to a live
  model-access preflight before demo use.
- Cloudflare Worker edge routing to a regional Supabase Function, which is the
  server-side OpenAI relay/proxy. The browser never receives provider keys,
  agent signer keys, ASC relayer keys, or Supabase service-role credentials.
- A truthful receipt model: a payment is shown as settled only when a
  successful target-chain receipt and a matching indexed `PaymentSettled`
  event are both present.

The MVP does not include production funds, fiat settlement, a physical card,
PAN/CVV handling, multi-chain support, ERC-20 payments, autonomous asset
conversion, or a production OpenAI fallback model.

## Operating Rules

1. Treat `process/features/pact/active/pact-mvp_08-09-26/` as the current
   execution source for the seven-phase MVP plan.
2. Treat `config/networks/advance-testnet.json` as the eventual network source
   of truth. A deployment manifest may record addresses, but it must parity
   check against this network configuration and cannot silently redefine it.
3. Use the shared `CanonicalIntentInput`, `policyVersion`, canonical hash,
   merchant conversion, native-asset descriptor, and typed error vocabulary
   from Phase 01. Do not create a second serializer or asset mapping in a
   downstream phase.
4. Keep off-chain preflight and on-chain policy checks aligned. Off-chain
   approval is advisory until the target-chain transaction succeeds.
5. Keep all external failure states explicit: provider unavailable, malformed
   model output, RPC mismatch, stale indexer data, failed receipt, and uncertain
   receipt must never be represented as a successful payment.
6. Never place secret values in source, fixtures, context, manifests, browser
   bundles, logs, or evidence artifacts. Use names only in documentation.
7. Only the explicitly approved live lane may mutate Advance Testnet state.
   Local fixtures and dry runs are the default during implementation.

## Key Patterns and Conventions

- **Canonical input:** Model output is parsed into strict
  `CanonicalIntentInput`; unknown keys and invalid values fail closed. The
  schema includes `policyVersion`, and the canonical hash uses a documented
  versioned field order.
- **Assets:** UI/API uses `native-testnet-ctc`; the contract adapter converts
  it to the native asset descriptor and `address(0)`. No ERC-20 branch is added
  to the MVP.
- **Merchant IDs:** Human merchant identifiers are converted to fixed
  `bytes32` using one shared helper. Contracts, preflight, indexer, and UI use
  the same representation.
- **Authority:** `PactCardController` is the policy authority; the pool does
  not expose a direct agent withdrawal path. The owner controls lifecycle;
  the agent signer can execute only the permitted payment path.
- **Settlement truth:** Receipt status, chain ID, transaction hash, event
  fields, and indexer confirmation are separate facts. The read model derives
  `settled` only from the two-signal rule described above.
- **Errors:** Stable typed error/reason codes are safe to expose; raw provider,
  RPC, database, or model payloads are not returned to the browser.
- **Configuration:** Static network identity and asset mapping live in the
  canonical network config. Runtime preflight checks chain identity, contract
  wiring, model access, secret presence by name, and allowed region.
- **Evidence:** Redacted JSON evidence packs are append-only records of
  commands, hashes, transaction identifiers, and explorer links. Secrets and
  personal payment-card data are excluded.

The browser may receive only intentionally public read/config values, such as

contract addresses. It must never receive any server-side signer, provider,
service-role, or relay secret.

## Security and Data Boundaries

Pact is a disposable testnet demonstration. Advance Testnet CTC has no fiat
value in this MVP. A virtual card is a policy-backed on-chain capability, not
a representation of a real PAN, CVV, bank account, or credit line. The UI must
show the testnet/no-fiat disclosure before setup and payment actions.

The Cloudflare Worker may handle public request routing and rate-limiting
signals, but the regional Supabase Function owns provider authentication,
model calls, agent execution authorization, and redacted error mapping. The
owner wallet signs owner-only contract actions; the agent signer is a separate
execution actor. Client state is never settlement truth.
